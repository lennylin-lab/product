# Spring Cloud Alibaba 微服务化改造

## Goal

将现有 Spring Boot 多模块单体规划为可分阶段实施、可验证、可回滚的 Spring Cloud Alibaba 微服务架构，在保持核心业务链路与外部 API 可用的前提下，形成清晰的服务边界、数据所有权、服务间契约和运维基线，为后续一次性重构与统一切换提供执行依据。

## Background

- 当前项目使用 Java 17、Spring Boot 3.5.0、MyBatis-Plus、Spring Security JWT、MySQL、Redis、Druid 和 ELK。
- 根工程包含 14 个 Maven 模块，但只有 `product-server` 一个启动入口；业务模块以进程内依赖方式聚合，当前属于模块化单体，而非微服务。
- 所有业务表位于同一份 `schema.sql`，使用同一数据源；认证、系统管理、需求、主数据、排程和执行模块共享领域实体及基础设施。
- 已确认存在跨候选服务边界的直接调用，例如 `product-auth -> product-system`、`product-demand -> product-pps`，以及执行事件驱动排程、批次、订单状态刷新的业务链路。
- 当前仓库已有 MySQL、Redis、ELK 的本地 Docker Compose 基础，但尚无注册配置中心、网关、服务调用、限流熔断、消息队列、分布式追踪或微服务部署编排。

## Requirements

- R1：技术底座采用与 Spring Boot 3.5.x 兼容的 Spring Cloud 与 Spring Cloud Alibaba 版本组合，实际实施前必须通过官方兼容矩阵锁定版本，不凭经验硬编码版本号。
- R2：规划必须给出目标服务边界及职责，边界以业务能力和数据所有权为依据，不按现有 Maven 模块一比一机械拆分。
- R3：规划必须覆盖注册与配置中心、API 网关、服务间同步调用、异步消息、认证授权、流量治理、可观测性、数据与事务、部署和密钥管理等组件选型，并说明采用或暂缓采用的理由。
- R4：规划必须给出数据库从共享 schema 过渡到服务自治数据的迁移路径，禁止目标态跨服务直接读写他方数据表。
- R5：规划必须识别并处理当前跨模块强耦合链路，包括认证查询用户权限、产品与工艺路线联动、执行事件到任务/批次/订单状态闭环，以及排程所需的订单和资源数据。
- R6：项目尚未上线，采用一次性重构、统一切换，不建设单体与微服务双轨运行、双写或灰度迁移机制；实施仍应分阶段开发与验证，最终统一验收。
- R7：统一切换后的外部 API 路径、JWT 登录语义和核心“订单 -> 批次 -> 排程 -> 执行 -> 完工”链路应尽量兼容；需要破坏性变更时必须显式列出。
- R8：本任务覆盖规划审核及后续微服务代码、数据库拆分、基础设施配置、部署编排、测试和文档实施；仅任务创建与规划审核所在会话不得修改产品代码和运行配置。
- R9：异步消息组件采用 RabbitMQ，不使用 RocketMQ 或 Kafka。

## Acceptance Criteria

- AC1：`design.md` 给出当前架构证据、目标架构、服务清单、职责边界、数据所有权、调用关系和关键业务数据流。
- AC2：`design.md` 给出 Spring Cloud Alibaba 及配套组件选型矩阵，每项包含用途、选择理由、替代方案或延后条件，并包含版本兼容验证要求。
- AC3：`design.md` 明确同步与异步通信边界、幂等/重试/超时/降级原则，以及跨服务一致性方案；不以分布式事务替代合理的服务边界设计。
- AC4：`design.md` 明确认证、网关、内部服务鉴权、配置与密钥、日志/指标/追踪、告警和审计方案。
- AC5：`implement.md` 将一次性重构拆成有顺序的内部实施阶段，列出每阶段变更范围、验证方式和回滚检查点，并以最终统一切换为完成条件。
- AC6：规划明确首个实施切片及进入条件，不引入为线上渐进迁移服务的临时双轨机制。
- AC7：规划审核后不存在阻塞性开放问题；用户在最终规划摘要之后明确批准，任务才可推进到 `in_progress`。
- AC8：任务创建与规划审核所在会话不产生产品代码或运行配置变更；后续会话按 `implement.md` 实施并通过对应阶段验收。

## Out Of Scope

- 本任务不重写现有排程算法、业务规则或前端页面。
- 本任务不承诺一次迁移即达到多活、跨地域容灾或超大规模流量能力。
- 本任务不立即引入所有可选中间件；没有明确业务需求支撑的组件应延后。
- 本任务不设计单体与微服务长期并行、线上灰度、双写或流量迁移方案。

## Constraints

- 必须使用 Spring Cloud Alibaba 作为核心微服务体系。
- 必须保留用户已有的未提交修改，尤其是 `product-server/src/main/resources/application-druid.yml`。
- 任务创建与规划审核所在会话不得落地产品代码；任务进入 `in_progress` 后，可在后续会话按已批准规划实施代码和配置。

## Key Decisions

- 项目尚未正式上线，采用一次性重构并统一切换；开发过程分阶段验证，但不维护新旧架构并行运行能力。
- 服务边界按业务能力和数据所有权划分，不与现有 Maven 模块一一对应。
- 中间件保持最小充分集合，没有明确需求的组件延后引入。
- 异步消息组件采用 RabbitMQ；当前业务侧重可靠投递、路由、重试和死信，不为尚不存在的高吞吐事件流需求引入 Kafka。
