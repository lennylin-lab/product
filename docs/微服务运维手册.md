> 依据：`.trellis/tasks/09-14-spring-cloud-alibaba-migration/`（PRD / design / ADR-0001~0005）与

## 1. 服务拓扑与端口

| 服务 | 端口 | 依赖 |
| --- | --- | --- |
| product-gateway（唯一外部入口） | 8080 | nacos, identity(JWKS) |
| product-identity | 8101 | identity_db, redis, rabbitmq |
| product-master-data | 8102 | master_data_db |
| product-demand | 8103 | demand_db, rabbitmq |
| product-planning | 8104 | planning_db, redis, rabbitmq |

基础设施：Nacos v3.0.3（8848/9848/控制台 8090）、RabbitMQ 3.13（5672/管理台 15673）、
MySQL 8.4（33066，六库：product + 5 个服务库）、Redis 7.4（6380）、Jaeger all-in-one（OTLP 4318/UI 16686）。

## 2. 启动顺序（Compose clean-room，Phase 6 实测 transcript：scratch/phase6/clean_room_up_transcript.txt）

1. **基础设施**：`docker compose -f compose.dev.yml up -d nacos rabbitmq jaeger`
   （MySQL/Redis 为宿主常驻实例；nacos/rabbitmq 健康 healthcheck 约需 30s）。
2. **Nacos namespace**：dev（v3 console API；v1 console 已 410，v1 config 读写仍可用）。
3. **Sentinel 规则**：发布网关流控规则 `product-gateway-flow-rules.json`（group=PRODUCT_GATEWAY），
   规则形如 `[{"resource":"identity-auth","grade":1,"count":200}]`。
4. **服务库初始化**：依次执行 5 个服务 `src/main/resources/db/init/*_schema.sql`
   （可重复执行 = 重置回种子状态；ADR-0005 独立库 + DML-only 账号）。
5. **启动服务**：identity → master-data → demand → planning → execution → gateway
   （生产顺序无硬依赖——服务对依赖缺失均为 fail-closed/降级，但按此顺序可消除启动期告警噪声）。
6. **冒烟**：`GET :8080/captchaImage` 200；6/6 注册 PRODUCT_GROUP；`/actuator/health` 全 UP。

一键脚本（Phase 6 演练用，含全部步骤）：`scratch/phase6/scripts/clean_room_up.sh`、`stop_all.sh`。

## 3. 备份 / 恢复 / 回滚

脚本：`scratch/phase6/scripts/cutover_drills.sh backup|restore|rollback`
（transcript：scratch/phase6/backup_transcript.txt、rollback_transcript.txt）。

- **备份**：`mysqldump --single-transaction --routines` 导出 6 库（product 单体旧库 + 5 服务库）。
- **恢复**：DROP → CREATE（utf8mb4/utf8mb4_unicode_ci）→ 逐库导入 → 表清单比对（77 张表一致）+
  关键表精确计数复核。注意 InnoDB `information_schema.table_rows` 为估算值，恢复比对以精确 COUNT 为准。
- **回滚演练（已实测通过）**：
  1. 关闭微服务入口（6 个 JVM 全停，8080/8101-8105 释放）；
  2. 恢复旧库备份（6 库 drop → import，表清单一致）；
  3. 单体可用冒烟：`mvn -pl product-server -am -DskipTests package` +
     `SPRING_DATA_REDIS_PASSWORD=... mvn -pl product-server spring-boot:run`（单体为普通 jar 打包，
     无 boot manifest，不能 `java -jar`），`GET :8081/captchaImage` 200；
  4. 冒烟完成后停止单体。
- **回滚触发条件**（design.md §7）：核心链路失败、数据校验不一致、认证不可用、关键 SLO 未达标。

## 4. 故障处理（常见故障 → 排查 → 补偿）

全部失败语义已在 Phase 6 故障注入中实测（transcript：scratch/phase6/fault_injection_transcript.txt）：

| 故障 | 现象（实测语义） | 排查 | 恢复/补偿 |
| --- | --- | --- | --- |
| 业务服务宕机 | 网关返回统一错误体 + X-Trace-Id：实例已注销 → 503「服务暂时不可用」；LB 缓存未失效的连接拒绝 → 500 | `ss -tlnp \| grep <port>`；Nacos 控制台服务列表 | 重启服务；恢复后网关自动路由（无需清缓存） |
| demand 宕机时排程 | schedule_job FAILED「需求服务不可用，无法加载排程输入快照」，任务保持 READY、无部分落库 | planning_db.schedule_job.error_message | 重启 demand 后重新发起排程（READY 任务自动纳入） |
| master-data 宕机时建订单行 | 「主数据服务不可用，无法校验产品引用，请稍后重试」（fail-closed，不静默放行） | demand 日志 MasterDataReferenceValidator | 重启 master-data 后重建订单行 |
| planning 宕机时执行命令 | execution 命令返回 200+「操作失败」（契约不可达 fail-closed），不留事件行 | execution 日志 PlanningContracts 调用失败 | 重启 planning 后重新下发命令 |
| RabbitMQ 宕机 | 命令仍成功（本地事务 + outbox），event_outbox PENDING 积压，消费方状态不推进 | execution_db.event_outbox 状态计数 | 重启 RabbitMQ：relay 自动重试排空，消费者重连收敛（ADR-0004 有界退避 8 次后 HALTED 待人工重放） |
| 事件投递 HALTED | outbox 行 status=HALTED（重试耗尽） | `/internal/<domain>/ops/health`（管理员 token） | 修复中间件后 `POST /internal/<domain>/ops/replay-outbox` |
| 消费失败进死信 | dead_letter_audit 出现未重放行（x-death reason=rejected） | `/internal/<domain>/ops/health` | `POST /internal/<domain>/ops/replay-dlq`（毒消息按设计再次死信，不丢不吞） |
| 状态漂移 | 对账 RECON_DRIFT | `recon.py report` | 本域定时对账自动修复（RECON_HEAL）；跨域差异见《数据补偿手册》 |
| 排程输入漂移 | schedule_job FAILED「排程输入数据已变化(...版本漂移...)」 | error_message 中两域版本号 | 排除并发写入后重新发起排程 |

## 5. 认证密钥管理（ADR-0003）

- **注入方式**：私钥经环境变量 `IDENTITY_JWT_PRIVATE_KEY`（PEM/PKCS#8）注入 Identity，
  不入库不入仓库；缺省时生成临时开发密钥（重启后 token 全部失效，仅限本地开发）。
  生成：`openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out key.pem`。
- **轮换（已实测，transcript：scratch/phase6/jwt_rotation_transcript.txt）**：
  1. 新私钥 KEY2 注入 `IDENTITY_JWT_PRIVATE_KEY`，旧公钥 pub1 注入
     `IDENTITY_JWT_PREVIOUS_PUBLIC_KEY`（PEM/X.509），重启 Identity；
  2. `/jwks` 同时发布两个 kid（轮换窗口），旧 token 在 TTL 内仍可验签，新登录由 KEY2 签发；
  3. 窗口关闭：去掉 PREVIOUS_PUBLIC_KEY 重启。**注意**：网关/服务侧 JWKS 按 kid 缓存
     （未知 kid 才触发刷新），撤销已缓存的 kid 需刷新缓存或重启网关/服务。
- 失效语义：认证失败 = HTTP 200 + body code 401（与单体错误契约一致），监控告警看 body code。

## 6. 已知单体缺陷处置结论（统一切换以服务侧行为为准）

以下均为单体存量缺陷（冻结，非本次迁移引入）；服务侧已修复或有等价/更优语义，切换后不再维护单体的这些路径：

1. **TableInfoCache 缺陷族**：单体 `/pps/product-route` 全部端点、`/demand/product` 创建/详情、
   排程 live 链路在当前源码运行时 500（ProductRoute/ProductMoldParam/MachineMoldCompatibility/
   ResourceCapability/ChangeoverRule 等实体无注册 Mapper，Db 工具链抛 Not Found TableInfoCache）。
   服务侧具备完整 Mapper 集，功能可用。**切换以服务侧行为为准**；如需修复单体内属新功能，需单独评审。
2. **单体 live 库 VARCHAR-ID + 非数字存量缺陷**：用户 live 库（product）ID 列为 VARCHAR(64) 且含
   非数字存量（如 customer_order.order_id='O1'/'O2'），单体执行事件刷新链
   `Db...in(ProductionBatch::getBatchId, <Long>)` 数字比较触发全列隐式 cast →
   `Data truncation: Truncated incorrect DOUBLE value` → /execute/event/start|pause|resume|complete
   全部 500 回滚。**处置结论**：属单体存量数据形态缺陷；微服务侧服务库 ID 列为 BIGINT、无此问题；
   统一切换以服务侧行为为准，切换后该缺陷随单体停用而消灭，不在单体内修复。
3. 单体 `/register`、`/logout` 未实现（baselines.md 冻结为不存在）；字典缓存 "default" 字段
   反序列化失败为单体冻结 bug（identity 等价复现）。

## 7. 告警基线

规则文件：`deploy/alerts/product-microservices-alerts.yml`（仅引用实测存在的指标族；
抓取需带 JWT——指标端点受保护，健康探针匿名）。覆盖：实例无指标（宕机）、5xx 错误率、
连接池 pending、排程线程池积压、堆压力、事件链消费停摆。
Outbox 滞留 / 死信未重放 / 对账差异为业务库事实：用 `scratch/phase6/scripts/validate_data.py`
（内置 recon.py report，drifts 非空即告警）在巡检通道执行。
P95 直方图开启方法：`management.metrics.distribution.percentiles-histogram.http.server.requests=true`。

## 8. 部署注意（镜像/Compose）

- 每服务含 Dockerfile（temurin 17 基线）；生产镜像构建 `mvn -pl product-services -am package`
  后逐服务 `docker build`。版本组合锁 ADR-0001（Boot 3.5.16 / SC 2025.0.3 / SCA 2025.0.0.0）。
- 生产秘钥（DB 密码、JWT 私钥、RabbitMQ 凭据）一律环境注入；`.env` 不入仓库（`.env.example` 为模板）。
- compose.dev.yml 为开发编排；生产需替换：MySQL/Redis/Nacos/RabbitMQ 为高可用实例、
  Jaeger 换 otel-collector + Tempo（可选）、加 Prometheus + Alertmanager 挂载 §7 告警规则。
- 内部契约端点（/internal/**）网关显式拒绝，仅内网可达；ops 端点需管理员权限（@ss.hasPermi('*:*:*')）。
